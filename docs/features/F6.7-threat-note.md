# F6.7 — threat note

**Feature.** Golden trace 8 plus the CSP / capability-denial / escape suite that docs/01 §6
names for FR-18 and docs/06 §8 gate 4 requires. Test and harness work only; it adds no
production surface.

**Trust zones touched.** None new. What changes is *evidence*: properties F6.4 and F6.5
implemented are now asserted end to end against live Postgres, the real HTTP routes, the
real bearer middleware, the real `AppBridge`, the real `policy::evaluate`, and the real
audit sink. Only the tool at the end of the chain and (for the denial matrix) the builder
worker are fakes — per CLAUDE.md's fixture-over-live rule, and because neither is what the
trace is about.

**The risk this feature exists to manage** is a *test* risk: an assertion that passes for the
wrong reason. Three cases were designed against explicitly.

1. *A refusal that would have been refused anyway.* The trace opens by exercising the
   **declared** capability successfully, so every refusal below is demonstrably a refusal and
   not a broken harness. It closes by asserting that across the entire matrix exactly **one**
   tool call ever happened — the legitimate one.
2. *A refusal nobody can observe.* Every rejection is asserted against a durable
   `app.capability_denied` row in Postgres, not against the error a caller happened to
   receive. That is the half of "undeclared capability ⇒ reject" that survives a refactor of
   the return type.
3. *A harness that papers over a real gap.* Pairing grants a device `["ui"]`, while every
   tool's `required_scopes` speaks a different vocabulary (`home:read`, `app:build`) — so a
   *real* paired device is denied every tool on the missing-scope arm. The trace grants its
   device the scope explicitly, in a commented block that says why, and the gap is written up
   as a gate finding rather than silently absorbed. Widening what a device is granted is an
   authorization decision (docs/11 §3, human-only), not a test fix.

**What the suite covers.**

* **Capability denial** — undeclared (at mint *and* at exchange), forged, malformed,
  replayed, cross-artifact and cross-version, each rejected, each audited, none reaching a
  tool. Expiry is deliberately *not* here: a 60-second wait is not a test, so the deadline is
  pinned by the domain table and the application table against a controlled clock.
* **CSP** — the served app document carries `sandbox allow-scripts` **without**
  `allow-same-origin`, `default-src 'none'`, `connect-src 'none'`, `form-action 'none'` and
  `base-uri 'none'`; the host's `<meta>` policy is the first thing in the document; and the
  blob route still returns the *same* artifact as `attachment`, so M3a's anti-execution
  control survived the milestone that added a render path.
* **Escape** — the builder cannot be walked out of its template directory: traversal,
  absolute paths, encoded traversal and unknown ids are all "unknown template", because ids
  are mapped through a closed table and never used as path components. An app id naming no
  artifact is a 404, not an empty document. The frame-level escape properties (opaque origin,
  no `allow-same-origin`, bytes only ever in `srcdoc`) are asserted in the web suite, where
  the DOM exists.

**Invariants.** No production code changes, so none are re-argued here; the suite's purpose
is to make invariant 1's M6 claim — *naming is not authorizing* — falsifiable rather than
asserted.
